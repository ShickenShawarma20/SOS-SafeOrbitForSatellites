# GLOSSARY OF TERMS

**Account**  
A financial container owned by a customer where funds are stored and transferred (e.g., Checking, Savings, Credit).

**Alert**  
A notification generated by the Risk Engine indicating that a transaction or entity has exceeded the acceptable threshold for fraud risk, requiring human review.

**AML (Anti-Money Laundering)**  
A set of laws, regulations, and procedures intended to prevent criminals from disguising illegally obtained funds as legitimate income.

**API (Application Programming Interface)**  
A set of protocols that allows different software components to communicate. In this project, it connects the React frontend to the FastAPI backend.

**Centrality**  
A graph analytics metric that identifies the most "important" or highly connected nodes within a network (e.g., PageRank or Degree Centrality).

**Classification**  
A machine learning task that assigns a label to an input. For FraudGraph AI, it is binary classification: Fraud (1) or Legitimate (0).

**Community Detection**  
Graph algorithms (like Louvain or Leiden) used to find clusters or densely connected groups of nodes, often indicative of fraud rings.

**Cypher**  
The query language used by Neo4j graph databases to retrieve and manipulate graph data using pattern-matching syntax.

**Device**  
The physical hardware (mobile phone, laptop, tablet) used to access an account or initiate a transaction.

**Edge**  
A connection between two nodes in a graph representing a relationship (e.g., "TRANSFERRED_FUNDS_TO", "LOGGED_IN_WITH").

**Embedding**  
A dense, low-dimensional vector representation of a node learned by a neural network, capturing its features and its structural position in the graph.

**Entity**  
A distinct object in the system (e.g., Customer, Account, Device, IP, Merchant) that becomes a node in the graph.

**Explainable AI (XAI)**  
Techniques and methods (like SHAP values) used to make the decisions of AI models understandable to human investigators.

**Fan-In**  
A graph topology pattern where multiple nodes direct edges toward a single central node (e.g., multiple victims sending money to a single mule account).

**Fan-Out**  
A graph topology pattern where a single node directs edges outward to multiple nodes (e.g., a compromised account distributing funds to many destinations).

**Feature**  
An individual measurable property or characteristic of an entity used as input for a machine learning model (e.g., "transaction amount", "node degree").

**Fraud Ring**  
An organized network of malicious actors operating multiple synthetic or stolen accounts in a coordinated manner.

**GAT (Graph Attention Network)**  
A type of Graph Neural Network that uses attention mechanisms to weigh the importance of different neighbor nodes during feature aggregation.

**GNN (Graph Neural Network)**  
A class of neural networks specifically designed to perform inference directly on graph-structured data.

**Graph**  
A mathematical structure consisting of nodes (vertices) connected by edges (links), used to model relationships.

**GraphSAGE**  
A Graph Neural Network architecture that generates node embeddings by sampling and aggregating features from a node's local neighborhood, allowing for scalability.

**IP (Internet Protocol Address)**  
The network address of the device used to access the system, acting as a critical node for identifying shared geographic or network origins.

**Knowledge Graph**  
An integrated data model representing entities and their relationships, infused with semantic meaning to enable deep querying across data silos.

**Label**  
The ground-truth answer in supervised machine learning (e.g., identifying a historical transaction definitively as "Fraud").

**Merchant**  
The business entity receiving funds in a commercial transaction.

**Message Passing**  
The core mechanism in GNNs where nodes iteratively share their feature information with their connected neighbors to update their own state.

**ML (Machine Learning)**  
The use of algorithms and statistical models that learn from data to make predictions without explicit programming.

**Mule Account**  
An account used by fraudsters to receive illicit funds and transfer them elsewhere, acting as a bridge to launder money.

**Neo4j**  
A highly popular, native graph database management system designed to store and traverse connected data efficiently.

**Node**  
A fundamental unit of a graph (also called a vertex), representing a specific entity (like an Account or Device).

**Precision**  
An evaluation metric: Out of all the transactions the model flagged as fraud, what percentage were *actually* fraud? (Focuses on minimizing False Positives).

**Recall**  
An evaluation metric: Out of all the *actual* fraud in the dataset, what percentage did the model successfully catch? (Focuses on minimizing False Negatives).

**Risk Score**  
A normalized numerical value representing the final calculated probability or severity of fraud for a given entity or event.

**ROC-AUC (Receiver Operating Characteristic - Area Under Curve)**  
A performance measurement for classification problems at various threshold settings. 

**PR-AUC (Precision-Recall - Area Under Curve)**  
A performance measurement highly preferred over ROC-AUC for severely imbalanced datasets (like fraud), as it focuses on the minority positive class.

**SHAP (SHapley Additive exPlanations)**  
A game-theoretic approach to explain the output of any machine learning model, assigning each feature an importance value for a particular prediction.

**Temporal Graph**  
A graph where nodes and edges possess time-based properties (timestamps), allowing the modeling of sequences and temporal dynamics.

**Transaction**  
An event representing the transfer of financial value between accounts at a specific time.

**Velocity**  
A derived feature measuring the rate or frequency of transactions over a specific time window.

**Weighted Graph**  
A graph where edges carry numerical values (weights), such as the dollar amount of a transaction.
